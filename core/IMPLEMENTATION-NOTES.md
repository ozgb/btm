# engine-core implementation notes

## What was built

`/work/core` is a Rust crate (`engine-core`, binary `core`), one static non-PIE musl x86_64 executable
(`.cargo/config.toml`: `+crt-static`, `relocation-model=static`; `readelf -d` shows no dynamic section, no
interpreter). It answers `core GROUP CALLS OUT` (docs/core-gate.md) for the groups below, one module each in `src/`:

| Group | File | Notes |
| --- | --- | --- |
| `rand` | `rand.rs` | streams, `RandomInt`, shuffle draw (spec section 5); the same `Rng` is what the host group's services use |
| `events` | `events.rs` | the 4096 record ring, two-record events, test/play overflow, drain |
| `commands` | `commands.rs` | orders a script by (tick, spawn < order < console, file line) |
| `console` | `console.rs` | words, `atoi` wrap, classes, cheat code, the events of the commands that need only the match setup (plus `control` and `view`) |
| `runtime` | `runtime.rs`, `runtime_tables.rs` | every entry of `/data/runtime/vectors`; small tables generated by `tools/gen_runtime_tables.py`; the 65536-entry sine/cosine table is computed on the fly in ~256-bit fixed point |
| `hash` | `hash.rs` | a port of the rows of `docs/trace-format.md` (checked against `tools/tracerehash.py`) |
| `loader`, `fuel` | `loader.rs` | manifest checks in the order of core-gate.md, memory and table, load, slots, data words, fuel at the first call of a tick, trap classes |
| `host` | `host.rs` | replay of a wind_meteors recording: block of the kit's `layout.json` offsets, services answered from the recording, `w` lines and closing `o` lines written from the module's block |
| `files` | not implemented | out of scope of this session |

`tools/gate.py` is a local gate (runs the core once per vector of `reference/core/<group>.json`, compares every line),
`tools/runtime_check.py` does the same for the runtime records, `tools/host_check.py` compares the host replay with the
full recordings of `tests/replay/wind_meteors/`.

## Crates

- `wasmi` 2.0.3 (features `std`, `validate`, `stable`): the WebAssembly runtime that hosts the module and the loader's
  fixtures. Pure Rust, links statically with musl, and reports trap codes, which the gate's error classes need.
  Engine fuel is off: metering is the module's own (`__fuel_set`, `__fuel_get`).
- `serde_json` 1: the manifest (a number with a fraction or an exponent, or above 2147483647, is refused as invalid
  JSON) and nothing else.

## Where the specs or the kit were unclear

- The module of /work/wind_meteors/ is for the interface 1.2, the kit is 3.1: see `SPEC-QUESTIONS.md`, Q1.
- `hash` row order: the doc says the order of the dump's blocks, `tracerehash.py` sorts: `SPEC-QUESTIONS.md`, Q2.
- The loader's `window_reaches` for a window that starts above a base: I refuse every window whose end is above the
  block base or the scratch base (the doc: "reaches"); no fixture tells them apart.
- Which manifest the `host` group loads the module with: the kit's `wasm/modules.json`, embedded in the core
  (`src/game_manifest.json`). The block, `Game` and `SimGlobals` are placed by the core (block offsets 0x1000 and
  0x50000) because the recordings name no address.
- The tick of the fuel budget in the `host` group is the call's `Game.ticks`: one budget for all the calls with the
  same tick (the load-time calls are all tick 0).
- The shuffle of a range (runtime entries `shuffle`, `load_sequence`): see `RUNTIME-NOTES.md`.
